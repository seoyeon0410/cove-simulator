# 엔지니어 요청서: 웹 모션을 로봇이 뷰포트와 똑같이 재생하게

웹(코브 애니메이터)에서 만든 모션을 로봇이 그대로 재생하게 하려고 합니다. 아래 4가지를 부탁드립니다.
급한 것은 **1번과 2번**이고, 3번과 4번은 그 뒤에 해도 됩니다.

## 1. 모션 파일 올리기 (필수)

웹의 연결 창 → "웹 모션을 로봇 파일로" → **로봇용 파일 받기 (.zip)** 으로 받은 `cove_web_motions.zip`을 첨부합니다.

| ZIP 안의 파일 | 할 일 |
|---|---|
| `motions/*.csv` (9개) | 로봇의 `~/robot-booth/motions/` 에 넣기 |
| `cove_scenes_web.py` | 안의 씬을 `cove_scenes.py` 에 추가하기 (저장하면 자동 반영) |
| `읽어보세요.txt` | 웹에서 로봇 한계로 잘린 구간 요약, 현재 방향 설정 |

- CSV 형식: 첫 줄 `t,id1,id2,id3,id4`, 0.1초 간격, **절대 틱**.
- 씬 이름은 `web_rest`, `web_tickle`, `web_snack`, `web_greet`, `web_praise`, `web_surprise`, `web_look`, `web_bye`, `web_expressions` 이고, 각각 `{"motion": "같은 이름"}` 한 줄입니다.
- 추가한 뒤 확인해 주세요.
  - `python3 cove_scene_check.py` 에서 경고 0
  - 씬이 끝나면 처음 자세로 돌아오는지
  - 정지 명령(`{"cmd":"stop"}`)에서 바로 멈추는지
- 등록되어 상태 메시지의 `scenes` 목록에 `web_*` 가 나타나면, 웹 동작 목록에 **▶ 웹과 같은 모션** 버튼이 자동으로 생깁니다.

웹에서 이미 적용한 한계 (엔지니어 답변서 기준)

| 관절 | 한계 |
|---|---|
| 기둥(neck, ID2) | 0° ~ 34° |
| 머리(head, ID3) | −46° ~ 0° |
| 갸웃(tilt, ID4) | 머리 각도별 허용 범위 (답변서 3-2 표) |
| 몸통(body, ID1) | ±90° (시험이 끝나면 ±180°까지 가능) |

## 2. 방향 확인 결과 알려 주기 (필수)

갸웃과 몸통은 방향이 아직 확정되지 않아서, 웹은 우선 아래처럼 가정했습니다.

- 웹 tilt + → ID4 +  (`ID4 = 2021 + 11.38 × tilt`)
- 웹 body + → ID1 +  (`ID1 = 1600 + 29.6 × body`)

`check_tilt`, `check_body` 시험 후 아래를 알려 주세요.

1. `check_tilt`: ID4 +80틱이 로봇 기준 **오른쪽** 갸웃인가요, **왼쪽** 갸웃인가요?
2. `check_body`: ID1 +296틱이 로봇 기준 **왼쪽**으로 도나요, **오른쪽**으로 도나요?

웹 기준은 다음과 같습니다.
- 웹 tilt + = 머리 위쪽이 로봇 기준 **오른쪽**으로 기웁니다.
- 웹 body + = 위에서 볼 때 **반시계(왼쪽)** 로 돕니다.

결과가 가정과 다르면 웹의 "갸웃 방향" / "몸통 방향" 선택을 바꿔서 파일을 다시 만들어 드리겠습니다.

## 3. 눈 표정 (다음 단계)

- 지금 로봇에는 `idle`, `blink`, `look_left`, `look_right`, `happy`, `closed`, `tickle`, `curious`, `heart`, `off` 10개만 있습니다.
- 웹은 표정이 16종이고, 쓸 수 있는 영역이 위 4줄 × 8칸이어서 **4줄 버전 비트맵**을 새로 만들어 JSON으로 드리겠습니다.
- 그 JSON을 로봇에 넣고, 씬 안에서 시간에 맞춰 표정을 바꿀 수 있게 해 주세요 (`{"eyes": "이름"}` 단계).

## 4. 실시간 조그 `pose` 명령 (선택)

```json
{"cmd": "pose", "deg": {"neck": 10, "head": -12, "tilt": 0, "body": 0}}
```

- 추가해 주시면 웹에서 재생하는 동안 로봇이 **실시간으로 같이** 움직이게 할 수 있습니다 (파일을 올릴 필요가 없어요).
- 단점은 와이파이가 끊기면 그 자리에서 멈춘다는 점입니다. 필수는 아닙니다.
- 추가한다면 범위를 넘는 값은 로봇이 자르고, 0.1초 간격(10Hz)으로 들어오는 것을 기준으로 해 주세요.

## 시험할 때

- 엔지니어가 **정지에 손이 닿는** 곳에서, **로봇 한 대**로 시작해 주세요.
- 첫 시험은 변화가 작은 `web_rest` 가 좋습니다. 그다음 `web_greet`, `web_tickle` 순서를 권합니다.
- 기구에 닿는 소리나 걸림이 보이면 바로 정지하고 알려 주세요.
- 웹과 로봇의 모션이 다르게 느껴지면, 어느 동작 몇 초쯤인지 알려 주세요. 웹에서 바로 맞춰 다시 드리겠습니다.

## 참고: 웹에서 알아 둘 점

- 웹 동작 중에는 머리를 −25° 이상 든 채 갸웃하는 구간이 많아서, 로봇 한계 때문에 **갸웃은 뷰포트(한계 해제 상태)보다 작게** 나옵니다. 뷰포트에서 "로봇 한계" 스위치를 켜면 로봇과 같은 모습으로 볼 수 있습니다.
- 웹 모션에는 물기(전류 제어) 동작이 없고, 위치 모드만 씁니다.
- 웹 모션은 접힌 자세(0°)에서 시작해서 끝에 제자리로 돌아옵니다. 시나리오6(깜짝 놀람)은 처음과 끝 자세가 같습니다.
