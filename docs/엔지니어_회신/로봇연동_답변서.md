## 1. 체크리스트 답변

### A. 하드웨어 / 모터

**1. 모터 개수·모델·ID·담당 관절**

| ID | 모델 | 로봇에서 부르는 이름 | 웹 관절 |
|---|---|---|---|
| 1 | XC330-T288 | 하부 회전 (바디 요) | body |
| 2 | XM430-W350 | 머리 들기 (기둥) | neck |
| 3 | XM430-W350 | 끄덕임 (헤드 피치) | head |
| 4 | XM430-W350 | 스위블 (헤드 롤, 갸웃) | tilt |

**2. 통신**: 프로토콜 2.0, 115200bps, U2D2 는 파이 USB(OTG) 에 연결, 포트 `/dev/ttyUSB0`. 로봇이 1대라 다른 로봇과의 차이는 없음.

**3. 제어 모드 / 속도·가속도**

| ID | 모드 | 비고 |
|---|---|---|
| 1 | 확장 위치(다회전) | 기어 약 2.6:1 이라 모터는 한 바퀴를 넘게 돎 |
| 2, 3 | 위치 (평소) / **전류 기반 위치 (물 때만)** | 씬에서 `current` 를 100 미만으로 주면 그 축이 전류 기반으로 바뀌어 그 힘 이상으로 누르지 않음 |
| 4 | 위치 | |

- 속도 상한: Profile Velocity 150 (모터 기준 약 206°/s → ID1 바디는 약 79°/s)
- 가속도: Profile Acceleration 10 (모터 기준 약 **215°/s²**, ID1 바디는 약 83°/s²)
- 씬의 각 동작은 "몇 초에 걸쳐 이동"으로 주면 로봇이 축마다 속도를 계산해 같이 도착시킴.
- → 웹 모션의 최대 가속도(200~800°/s²)가 이보다 크면 로봇에서는 조금 부드럽게(늦게) 따라갑니다. 웹에서 가속도를 **약 200°/s² 이하**로 맞추면 거의 같게 보입니다.

**4. 0점·방향·감속비·가동 한계** → 아래 **2번 관절 매핑**에 정리.

**5. 토크·전류 제한, 전원 인가**
- 평소(모션 쇼): 위치 모드 + 출력 상한(Goal PWM 400/885 ≈ 45%) — 손이 끼었을 때를 대비한 힘 제한.
- 물 때: 씬에서 `{"current": {3: 60}}` 처럼 주면 그 축만 전류 기반(1 ≈ 2.7mA)으로 바뀜. 끝나면 `{"current": {3: 100}}` 로 되돌림.
- 전원을 켜면 **현재 자세에서 토크를 켜고 처음 자세(접힌 자세)로 천천히** 이동. 갑자기 튀지 않음.
- ID2(목)는 씬이 돌 때만 토크를 켜고, 가만히 있을 때는 끔 (스프링이 받쳐 줌).
- 과열·과부하: 모터 자체 보호(하드웨어 에러)가 걸리면 로봇이 동작을 멈추고 "모터 전원을 껐다 켜야 함"을 알림.

**6. 바디 회전**: 무한 회전 아님. 처음 자세에서 **좌우 약 180°** 까지 가능(소프트웨어로 제한). 전원은 처음 자세 근처(±반 바퀴)에서 켜야 함.

### B. 제어기 / 소프트웨어

**7.** Raspberry Pi OS Lite (trixie) 32비트, Python 3.13.5. 로봇 프로그램 `cove_robot.py` (dynamixel-sdk + paho-mqtt), systemd 로 부팅 시 자동 실행.

**8. 받을 수 있는 명령** (MQTT, 토픽 `booth/robot2/cmd`, JSON)

| 명령 | 뜻 |
|---|---|
| `{"cmd":"scene","name":"bite"}` | 씬 실행 (씬 이름만 보내도 됨: `"bite"`) |
| `{"cmd":"stop"}` | 정지 — 그 자리에서 힘 유지 |
| `{"cmd":"torque","on":false}` / `true` | 토크 끄기 / 켜기 |
| `{"cmd":"eyes","mode":"happy"}` | 눈 표정 |
| `{"cmd":"mode","name":"rest"}` | 센서 반응 모드 (rest / tickle / snack / track / off) |
| `{"cmd":"reload"}` | 씬 파일 다시 읽기 (저장하면 자동으로도 다시 읽음) |

- 전체 정지: `booth/all/cmd` 에 `{"cmd":"stop"}`
- 로봇 상태(1초마다): `booth/robot2/status` (모터 위치·온도·전압, 센서 값, 씬 목록 등)
- 로봇 로그: `booth/robot2/event`
- **웹에서 바로 연결 가능**: 브로커가 웹소켓 `ws://192.168.1.232:9001` 을 열어 두므로, 웹 페이지에서 mqtt.js 로 접속해 위 명령을 보낼 수 있습니다 (부스 대시보드 `http://192.168.1.232:8000` 이 이 방식).
- 실시간 각도 스트리밍(조그) 명령은 아직 없음 → 필요하면 추가 가능 (예: `{"cmd":"pose","deg":{"neck":10,"head":-12,"tilt":0,"body":0}}`).

**9. 모션 파일 올리기**: SSH/SCP (`~/robot-booth/` 폴더). 씬은 `cove_scenes.py` 한 파일이고, 저장하면 1초 안에 로봇이 자동으로 다시 읽음 (재시작 불필요). 웹 담당용 SSH 키는 이미 등록되어 있음 (`cove-designer`, 아래 3번).

**10. 단위·주기**
- 로봇 내부 단위는 **다이나믹셀 틱** (4096 = 한 바퀴, 1° ≈ 11.38틱). 각도(°) → 틱 변환식은 2번 표.
- 씬 단계 형식: `{"rel": {2: -120, 3: -150}, "time": 2}` = 처음 자세 대비 틱으로, 2초에 걸쳐 이동.
- 프레임 재생: 0.1초 간격 프레임을 그대로 재생하는 기능 있음 (`{"motion": "이름"}` → `motions/이름.csv`, 3프레임 앞을 목표로 속도를 맞춰 감). 갱신 주기는 0.1초(10Hz) 권장.

**11. 눈 (HT16K33)**: I²C 주소 **왼쪽 0x70 / 오른쪽 0x71** (로봇 기준). 쉘 구조상 **8×8 중 위 4줄 × 8칸만** 사용. 비트 7 = 왼쪽 칸, 행/열 반전 없음. 지금 있는 표정: `idle`(뜬 눈, 자동 깜빡임), `blink`, `look_left`, `look_right`, `happy`, `closed`, `tickle`, `curious`, `heart`, `off`. 표정 이름을 보내는 방식(로봇이 비트맵 보유)으로 쓰고 있음 — 웹 표정 16종을 4줄로 맞춰 주시면 로봇에 넣겠습니다.

**12. 센서**

| 센서 | 위치 | 상태값 (`status.sense`) |
|---|---|---|
| VL53L5CX 다구역 ToF (4×4, 10Hz) | 전면 | `front_mm` 가장 가까운 거리, `person` (50cm 안 1초), `dir` 사람 방향 −1 왼쪽 ~ +1 오른쪽. 4×4 값은 `booth/robot2/tof` 로 0.2초마다 |
| VL53L0X ToF | 위 쉘 (아래를 봄) | `top_mm`, `arm` (팔/손이 들어옴) |
| TTP223 터치 ×3 | 머리 (왼/가운데/오른) | `touch` |
| LD2410C 레이더 | — | **사용 안 함** (근거리에서 불안정해 제외) |

센서 반응 시나리오(휴식/간지럽히기/간식/따라보기)는 로봇 안에서 판단해 씬 조각을 틉니다. 임계값은 `cove_robot.py` 위쪽 상수 (예: 사람 50cm, 간식 소품 20cm, 떠남 5초).

**13. 비상정지·끊김**: 대시보드 "전체 정지"(모든 로봇 정지) / "토크 해제". 로봇이 씬을 자체 재생하므로 와이파이가 끊겨도 **현재 씬을 끝까지 하고**, 씬은 처음 자세로 끝나도록 만듦. 휴식 시나리오에서 팔이 머리 밑에 있을 수 있을 때는 정지·종료 시에도 반드시 머리를 들어 놓아주는 씬을 먼저 실행.

### C. 네트워크

**14.** 로봇 1대 (부스 전체로는 다른 로봇들도 같은 공유기 사용). 공유기 **TP-Link AX53**, 와이파이 **`HIDELAB_ROBOWORLD`** (2.4GHz, 채널 7, WPA2). 비밀번호는 담당자에게 따로.
**15.** DHCP 주소 예약 — 코브 = **`192.168.1.88`** (`cove.local` 로도 찾아짐). 부스 PC = `192.168.1.232` (유선).
**16.** 같은 서브넷 192.168.1.x, 로봇 ↔ PC 통신 확인됨 (클라이언트 격리 꺼짐).
**17.** 부스 PC 가 같은 공유기에 유선 연결. 전시장에서는 **인터넷 없이** 동작 (공유기 WAN 선만 뺌).
**18.** 파이 시계는 평소 인터넷 NTP. 전시장(오프라인)에서는 시계가 틀어질 수 있으나 **로봇 1대라 동시 시작 동기화는 필요 없음** (명령 받은 즉시 재생).

### D. 전시 운영

**19.** 1대라 동시/개별 구분 없음. 센서 트리거 규칙은 디자이너 요청서(`COVE_센서_요청서.md`) 표대로 구현되어 있음 (예: 전면 50cm 안 1초 → 시작).
**20.** 전시 시간 수~금 10:00~17:00, 토 10:00~16:00. **전원을 켜면 자동 시작**하고 처음 자세로 감.

## 2. 관절 매핑 (웹 각도 → 모터 틱)

각도 기준은 웹과 같게 **접힌 기본 자세 = 0°** (로봇의 "처음 자세"와 같음). 1° = 11.378틱 (4096/360).

| 웹 관절 | 모터 | 처음 자세(틱) | 변환식 (틱) | 방향 |
|---|---|---|---|---|
| neck | ID2 | 3201 | **ID2 = 3201 − 11.38 × neck** | 목이 설수록 틱 감소 (확인됨) |
| head | ID3 | 3074 | **ID3 = 3074 + 11.38 × head** | 얼굴이 위로(웹 음수) 갈수록 틱 감소 (확인됨) |
| tilt | ID4 | 2021 | **ID4 = 2021 ± 11.38 × tilt** | **부호 확인 필요** (로봇 기준 오른쪽으로 갸웃이 + 인지 −인지) |
| body | ID1 | 1600 | **ID1 = 1600 − 29.6 × body** (로봇 기준 오른쪽 회전을 + 로 할 때) | 틱 증가 = 로봇 기준 왼쪽 회전 (따라보기 시험에서 확인). 기어 약 2.6:1 → 1° ≈ 29.6틱 |

- ID2·ID3 은 모터 축 = 관절(1:1)로 판단 (측정 가동 폭이 웹 범위와 거의 같음: 목 34° / 고개 47°). 실물로 한 번 확인 권장 (3번의 확인 절차).
- 웹 `head` 가 **목(neck) 기준 상대각**이어야 로봇과 맞습니다 (ID3 는 목 위에 달려 있어 목과 같이 움직임). 월드 기준이면 `head_로봇 = head_웹 − neck` 같은 변환이 필요 — 웹 쪽에서 어느 쪽인지 알려 주세요.

## 3. 웹 범위를 실제 로봇에 맞추기

### 3-1. 실제 가동 범위 (도, 로봇이 최종적으로 잘라 내는 값)

| 관절 | 웹 현재 범위 | **실제 범위** | 웹에서 할 일 |
|---|---|---|---|
| neck | 0° ~ 35° | **0° ~ 34°** | 상한 34° |
| head | −50° ~ +8° | **−46.5° ~ 0°** | 상한 **0°** (처음 자세가 아래쪽 끝이라 더 숙일 수 없음), 하한 −46° |
| tilt | 약 −25° ~ +25° | **최대 약 ±15°, head 각도에 따라 다름** (아래 표) | head 별 허용 범위로 제한 |
| body | 약 −12° ~ +12° | 약 ±180° | 그대로 (더 크게 써도 됨) |

### 3-2. tilt(갸웃) 허용 범위 — head 각도에 따라 다름

머리가 맨 아래나 맨 위 근처에 있으면 기구가 잠겨서 **갸웃할 수 없습니다** (실측). 아래는 실측점이고 사이는 직선으로 이어서 쓰면 됩니다. 로봇은 여기서 다시 양쪽 약 1.8°(20틱) 여유를 두고 자릅니다.

| head (°) | tilt 최소 ~ 최대 (°, ID4 + 방향 기준) |
|---|---|
| 0 (처음 자세) | 0 ~ 0 (잠김) |
| −2.8 | −7.1 ~ +9.1 |
| −7.2 | −8.0 ~ +4.9 |
| −12.0 | −13.9 ~ +6.9 |
| −25.4 | −15.3 ~ +14.9 |
| −27.2 | −6.5 ~ +7.6 |
| −40.5 | 0 ~ 0 (잠김) |
| −43.8 | 0 ~ 0 (잠김) |
| −47.8 | 0 ~ 0 (잠김) |

- 손으로 잰 값이라 들쭉날쭉합니다. **head −10° ~ −30° 구간에서 tilt ±7° 정도**로 쓰면 어디서든 안전합니다.
- tilt 의 +/− 가 로봇 기준 어느 쪽인지는 3-4 에서 확인 후 표의 부호를 맞춥니다.

### 3-3. 속도·가속도
- 관절 속도 **약 200°/s 이하** (바디는 약 80°/s 이하), 가속도 **약 200°/s² 이하**로 맞추면 웹과 로봇이 거의 같게 보입니다. 이보다 빠른 구간은 로봇이 조금 늦게 따라가며 부드러워집니다.
- 실제로 2026-10 시험에서 0.2~0.4초마다 목표가 바뀌는 빠른 동작도 재생됐고, 오히려 위치 모드가 살짝 늦게 따라가며 부드럽게 보였습니다.

### 3-4. 방향·0점 확인 절차 (로봇을 받았을 때 한 번)
1. 로봇 전원을 켜면 처음 자세(웹 0°, 0°, 0°, 0°)로 갑니다. 웹 모델의 기본 자세와 눈으로 비교.
2. 아래 확인용 씬을 `cove_scenes.py` 에 넣고 실행 (1번 관절씩, 작은 각도):
   ```python
   "check_neck": [{"rel": {2: -228}, "time": 2}, {"wait": 2}, {"rel": {2: 0}, "time": 2}],          # neck +20°
   "check_head": [{"rel": {2: -228, 3: -228}, "time": 2}, {"wait": 2}, {"rel": {2: 0, 3: 0}, "time": 2}],  # neck 20°, head −20° (얼굴 위)
   "check_tilt": [{"rel": {2: -228, 3: -228}, "time": 2}, {"rel": {4: 80}, "time": 1}, {"wait": 2},
                  {"rel": {4: 0}, "time": 1}, {"rel": {2: 0, 3: 0}, "time": 2}],                    # 갸웃 ID4 +7° — 어느 쪽인지 보기
   "check_body": [{"rel": {1: 296}, "time": 2}, {"wait": 2}, {"rel": {1: 0}, "time": 2}],          # 로봇 기준 왼쪽 10° 예상
   ```
3. 같은 각도를 웹에 넣고 모양이 같은지 비교. 각도가 다르면 1:1 이 아닌 것이니 실제 각도를 알려 주세요 (변환 계수를 고침).
4. `check_tilt` 에서 로봇이 **로봇 기준 어느 쪽으로 갸웃했는지** 알려 주시면 tilt 부호를 확정합니다.

## 4. 로봇을 받아서 직접 움직이기

### 4-1. 준비 (한 번)
1. 노트북을 와이파이 **`HIDELAB_ROBOWORLD`** 에 연결 (부스 PC 와 같은 공유기).
2. SSH 키 접속: 이미 등록된 `cove-designer` 키(`~/.ssh/cove_key`)로 `ssh -i ~/.ssh/cove_key sh@192.168.1.88` (자세한 설정은 같은 폴더 `CLAUDE.md` / `COVE_시작하기.md`).
3. 부스 PC 에서 `RobotBooth.exe` 가 켜져 있으면 대시보드 **`http://192.168.1.232:8000`** 에서 씬 버튼·정지·토크 해제를 바로 쓸 수 있습니다.

### 4-2. 씬 실행 / 정지 (로봇 안에서)
```bash
cd ~/robot-booth
python3 cove_cmd.py list          # 씬 목록
python3 cove_cmd.py bite          # 씬 실행 (씬 이름만)
python3 cove_cmd.py stop          # 정지 (그 자리 유지)
python3 cove_cmd.py torque_off    # 토크 해제 (머리가 처질 수 있음 — 손으로 받칠 것)
python3 cove_cmd.py eyes happy    # 눈 표정
python3 cove_cmd.py log           # 최근 로그
```

### 4-3. 웹에서 모션을 만들어 로봇에 넣기
- **간단한 동작**: `cove_scenes.py` 에 단계로 적기 (`rel` 틱 + `time` 초, `eyes`, `wait`, `repeat`). 저장하면 자동 반영, 대시보드에 버튼이 자동으로 생김. 저장 전 `python3 cove_scene_check.py` 로 범위·속도 검사 (경고 0 이 목표).
- **웹 프레임 그대로**: 웹 JSON(`frames` 0.1초 간격, `[t, neck, head, tilt, body]`)을 2번 변환식으로 틱으로 바꿔 `motions/이름.csv` 로 저장하면 `{"motion": "이름"}` 한 줄로 재생됩니다.
  - CSV 형식 (첫 줄 머리글, 위치는 **절대 틱**):
    ```
    t,id1,id2,id3,id4
    0.0,1600,3201,3074,2021
    0.1,1600,3198,3070,2021
    ```
  - 눈은 같은 씬에 `{"eyes": "..."}` 단계를 시간에 맞춰 넣거나, 변환기가 씬을 만들어 주면 됩니다. 변환기(웹 JSON → CSV + 씬)는 원하시면 저희가 만들어 드립니다.
- **웹에서 직접 트리거**: `ws://192.168.1.232:9001` 에 접속해 `booth/robot2/cmd` 로 `{"cmd":"scene","name":"..."}` 를 보내면 됩니다.

### 4-4. 안전 규칙
- 처음 움직일 때는 **사람이 옆에서** 전원/정지에 손이 닿게. 새 씬은 작은 각도부터.
- 범위를 넘는 값은 로봇이 자동으로 자르지만, 기구에 닿는 소리나 걸림이 보이면 바로 정지하고 알려 주세요.
- 물기(사람 손) 동작은 반드시 `current` 를 100 미만(예: 60)으로 낮춘 구간에서만, 손에 닿기 **전**에 넣기 (바뀌는 순간 머리가 약 2° 처짐).
- `cove_scenes.py` 외의 파일은 수정하지 않기.
