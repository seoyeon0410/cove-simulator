# 코브 애니메이터 인수인계 (2026-10-28 기준)

코브(COVE) 로봇의 모션·표정을 웹에서 만들고, 같은 모션을 실제 로봇이 재생하게 하는 도구입니다.
GitHub: https://github.com/seoyeon0410/cove-simulator (작업은 `main`에 바로 올립니다)

---

## 1. 한눈에 보기

| 하는 일 | 어디서 |
|---|---|
| 8개 시나리오 + 표정 모음을 3D로 재생·편집 | 웹 (뷰포트·타임라인) |
| 눈 표정(8×8 도트) 고르기·끌어서 만들기 | 오른쪽 패널 "눈 만들기" |
| 관절(기둥·머리·갸웃·몸통)을 슬라이더로 움직여 로봇 범위 확인 | 오른쪽 패널 "관절 조작" |
| 로봇에 연결해 씬 실행·정지·토크·눈 바꾸기 | 헤더 "로봇 연결" |
| 웹 재생을 로봇이 실시간으로 따라 하기 | 헤더 "로봇 동기" |
| 웹 모션을 로봇용 파일(CSV·눈 JSON)로 내보내기 | 로봇 연결 창 → "웹 모션을 로봇 파일로" |

## 2. 실행

```bash
cd "cove 시뮬레이터"
python3 server.py 5173
```
브라우저에서 http://localhost:5173 을 엽니다. (`server.py`는 캐시 없이 여러 요청을 동시에 처리하는 정적 서버입니다. 23MB GLB를 불러올 때 단일 서버는 끊겨서 이렇게 만들었습니다.)

- 로봇을 쓰려면 노트북이 와이파이 **`HIDELAB_ROBOWORLD`** 에 연결되어 있어야 합니다.
- 작업 내용은 브라우저 `localStorage`에 자동 저장됩니다. 저장 형식이 바뀌면 `app.js`의 `SAVE_VERSION`을 올립니다(현재 20).

## 4. 모션이 만들어지는 과정

1. `presets.js`의 키를 PCHIP으로 0.1초 간격으로 다시 샘플하고, 스프링 추종(`SPRING`)과 미세한 흔들림(`microSway`)을 더합니다.
2. 목을 먼저 들고 머리는 그 뒤에 따라오게 합니다(`sequenceNeck`, 처음 3초는 건너뜀). 끝에 처음 자세로 돌아오는 구간(`withTail`)을 붙입니다.
3. 머리와 폼(몸체)이 겹치지 않도록 머리 각도를 보정합니다(`clearHeadFromBody`).
4. 뼈 회전은 **쉬는 자세를 0°** 로 두고 기둥·머리는 로컬 Z축, 갸웃·몸통은 로컬 Y축으로 돕니다.
   - 기둥 0~35°(0 = 접힘), 머리 −50~+8°(음수 = 얼굴이 위), 머리는 **기둥에 대한 상대각**입니다. 머리가 수평일 때는 대략 `머리 ≈ −1.2 × 기둥`.
   - 갸웃 +는 머리 위쪽이 로봇 오른쪽으로 기웁니다. 몸통 +는 위에서 볼 때 반시계(로봇 왼쪽)입니다.
5. 뷰포트의 **"로봇 한계"** 스위치(기본 ON)를 켜면 로봇이 못 하는 각도는 잘라서 보여 줍니다. 키 값은 그대로입니다.

## 5. 로봇 쪽 정보

### 5-1. 접속
| 항목 | 값 |
|---|---|
| 로봇 | 라즈베리파이 `cove` (`sh@192.168.1.88`, `cove.local`), 로봇 이름 `robot2` |
| 와이파이 | `HIDELAB_ROBOWORLD` (공유기) |
| MQTT 브로커 | `192.168.1.232` — 웹소켓 포트 **9001**(웹이 사용), MQTT 포트 1883 |
| 부스 대시보드 | http://192.168.1.232:8000 (씬 버튼·정지·토크 해제) |
| 로봇 프로그램 | systemd 서비스 `robot-client.service` (`cove_robot.py --id robot2`, 부팅 시 자동 시작) |
| 로봇 로그 | `ssh cove 'journalctl -u robot-client -n 60 --no-pager'` |

비밀번호 로그인은 막혀 있고 **SSH 키만** 됩니다. 새 컴퓨터에서 쓰려면:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/cove_key -N "" -C cove-designer
```
```bash
printf '\nHost cove\n    HostName 192.168.1.88\n    User sh\n    IdentityFile ~/.ssh/cove_key\n' >> ~/.ssh/config
```
`~/.ssh/cove_key.pub` 한 줄을 엔지니어에게 보내 로봇의 `~/.ssh/authorized_keys`에 등록받습니다. 등록 후 `ssh -o BatchMode=yes cove echo ok`가 `ok`면 성공입니다. **비밀 키(`cove_key`)는 누구에게도 보내지 마세요.** 지금 로봇에는 키가 3개 등록되어 있습니다(이 노트북 키, 이전 디자이너 키, 엔지니어가 만든 새 키).

### 5-3. 모터와 변환식
| 웹 관절 | 모터 | 틱 변환 (1° = 11.378틱) | 웹 한계 |
|---|---|---|---|
| 기둥 | ID2 | `3201 − 11.38 × °` | 0 ~ 34° |
| 머리 | ID3 | `3074 + 11.38 × °` | −46 ~ 0° |
| 갸웃 | ID4 | `2021 ± 11.38 × °` (**부호 확인 중**) | 머리 각도별 허용 범위(최대 ±15°) |
| 몸통 | ID1 | `1600 + 29.6 × °` (확정) | ±90° (로봇은 ±180°) |

- 갸웃은 머리가 맨 아래·위 근처이면 기구가 잠겨 움직이지 못합니다(`robotexport.js`의 `TILT_ENV`).
- 관절 속도 약 200°/s, 몸통 약 80°/s, 가속도 약 200°/s² 이하로 맞추면 웹과 로봇이 거의 같게 보입니다.
- 기둥(ID2)은 평소에 토크를 끄고 씬이 돌 때만 켭니다(스프링이 받침).

### 5-4. 로봇 명령 (토픽 `booth/robot2/cmd`, 전체는 `booth/all/cmd`)
| 명령 | 설명 |
|---|---|
| `{"cmd":"scene","name":"web_greet"}` | 씬 실행 |
| `{"cmd":"stop"}` | 정지 (몸통·머리·갸웃은 그 자리, 기둥은 힘을 빼서 조금 내려올 수 있음). 센서 반응도 꺼짐 |
| `{"cmd":"torque","on":true}` | 토크 켜기(현재 위치 유지) / 끄기 |
| `{"cmd":"eyes","mode":"하트 눈"}` | 눈 표정 (한글 표정 이름 그대로) |
| `{"cmd":"mode","name":"rest"}` | 센서 반응 모드 (rest / tickle / snack / track / off) |
| `{"cmd":"pose","deg":{"neck":10,"head":-12,"tilt":0,"body":0}}` | 실시간 조그. 0.1초 간격 기준, 2초 안 오면 끝나고 그 자세 유지. 씬 도중엔 씬을 멈추고 조그로 넘어감, "휴식" 시나리오 중엔 무시 |
| `{"cmd":"reload"}` | 씬 파일 다시 읽기 |

상태는 `booth/robot2/status`(1초마다), 이벤트는 `booth/robot2/event`로 옵니다.

## 6. 웹 ↔ 로봇 사용법

### 6-1. 연결
헤더 **로봇 연결** → 주소 `ws://192.168.1.232:9001`, 이름 `robot2` → **연결**. "상태 수신 중"이 뜨면 됩니다.
**연결하기 전에는 로봇에 아무 명령도 보내지 않습니다.** 움직이는 명령(씬 실행·로봇 동기·관절 조작 전송)은 "로봇 주변을 확인했어요"를 체크해야 나갑니다. 연결이 끊기면 체크가 풀리고, 새로고침하면 연결과 동기가 모두 꺼집니다.

### 6-2. 움직이기
- **저장된 웹 모션을 로봇이 재생**: 동작 목록에서 동작을 선택 → `▶ 웹과 같은 모션`. (로봇에 `web_*` 씬이 있어야 보입니다.) 웹 화면과는 별개로 로봇이 처음부터 끝까지 재생합니다.
- **웹 재생을 로봇이 실시간으로 따라 하기**: 헤더 **로봇 동기**를 켜고 웹에서 재생. 0.1초마다 지금 자세를 `pose`로 보내고, 웹을 멈추면 `stop`도 보냅니다. 눈 표정도 같이 보냅니다.
- **정지**: 헤더 `■ 정지`(항상 보임), 연결 창의 `전체 정지`. 토크 해제는 두 번 눌러야 실행됩니다.
- **로봇 기본 씬**: 동작 목록의 선택한 동작 아래(`장면별`, `관련`)와 맨 아래 `로봇 전용`(토토로, 기본 자세 등).

### 6-3. 새 웹 모션을 로봇에 올리기 (제일 중요한 절차)
1. 웹에서 모션을 고칩니다.
2. 로봇 연결 창 → "웹 모션을 로봇 파일로"에서 갸웃·몸통 방향을 확인하고 **로봇용 파일 받기 (.zip)**.
3. ZIP 안의 `motions/*.csv`를 로봇 `~/robot-booth/motions/`에, `cove_eyes.json`을 `~/robot-booth/cove_eyes.json`에 올립니다(위 5-2의 백업 후 `scp`).
4. 새 `web_*` 씬이 늘어났다면 `cove_scenes_web.py`의 항목을 엔지니어가 `cove_scenes.py` 맨 끝 구간에 추가해야 합니다. (그래야 디자이너용 "1.2배 느리게 + 끝에 5초 멈춘 뒤 내려앉기" 후처리를 안 받습니다.)
5. 이름 연결은 `robotmap.js`의 `LINKS`에 씁니다(예: `'휴식': { web: 'web_rest', main: 'rest', ... }`). 이름을 바꾼 동작·직접 만든 클립은 연결되지 않습니다.

## 7. 눈 표정

- 눈 하나 = 8×8 LED 도트(HT16K33, I²C 0x70/0x71). 로봇 쉘 구조상 **위 4줄 × 8칸만** 보입니다.
- 웹 뷰포트는 8줄이고(`look.js`), 로봇은 4줄로 다시 그렸습니다(`roboteyes.js`). 모양이 완전히 같지는 않습니다.
- 표정 14종: 뜬 눈, 감은 눈, 웃는 눈, 졸린 눈, 놀란 눈, 하트 눈, 반짝 눈, 슬픈 눈, 신난 눈, 윙크, 편안한 눈, 별 눈, 눈물 눈, 점 눈. (초롱 눈·또렷한 눈·가로 눈은 일부러 뺐습니다.)
- **눈 만들기**: 눈 그림을 끌어서 왼쪽·오른쪽 눈에 넣거나(눈별 표정 `eL`/`eR`), 타임라인 맨 아래 눈 줄에 놓으면 그 시간부터 바뀝니다. "내 표정 저장"으로 조합을 보관합니다. 한쪽 눈 표정은 웹에서만 보이고, 로봇의 눈 JSON은 아직 한쪽씩 따로 읽지 못합니다.
- 깜빡임은 뜬 눈일 때 3.8초 주기(처음 1.6초), 4프레임 60ms입니다.

### 실물 LED의 알려진 특성 (중요)
2026-10-28 실물 시험으로 확인했습니다.
1. 로봇 쪽 `left`는 **정면에서 볼 때 왼쪽 눈**, `right`는 오른쪽 눈이고, 글자 순서도 정면에서 본 왼쪽→오른쪽입니다(좌우를 뒤집지 않음).
2. LED는 적어 준 칸보다 **한 칸 오른쪽**에 켜지고 **맨 오른쪽 칸은 맨 왼쪽으로 넘어갑니다.**
3. 그래서 `cove_eyes.json`의 글자는 **미리 왼쪽으로 한 칸 돌려서** 적어 둡니다(`roboteyes.js`의 `HW_ROTATE = 1`, 파일 안에도 `hw_rotate`로 적힘). `docs/눈표정_4줄.md`의 그림은 보정 전(보이길 원하는) 모양입니다.
4. 두 눈 사이를 최대한 벌리려고 왼쪽 눈은 맨 왼쪽, 오른쪽 눈은 맨 오른쪽 열까지 밀어 둡니다(`OUTER_MARGIN`).
5. 엔지니어가 로봇 프로그램에서 이 한 칸 어긋남을 고치면 `HW_ROTATE`를 0으로 바꿔 파일을 다시 만들어야 합니다. **엔지니어가 고치기 전에 알려 달라고 해야 눈이 깨지지 않습니다.**
6. 표정 버튼과 로봇 동기는 `idle`/`happy`/`heart` 같은 로봇 기본 이름이 아니라, 눈 파일의 한글 이름 그대로 보냅니다(기본 이름은 옛 모양이라 깨져 보임).

## 9. 지금 남은 일 / 주의

1. **`check_tilt`**: 갸웃 방향(ID4 +가 로봇 기준 오른쪽인지)은 엔지니어가 실물로 확인 중입니다. 반대면 연결 창 "갸웃 방향"을 `−`로 바꿔 ZIP을 다시 만들고, 로봇의 부호도 맞춰야 합니다. 몸통은 확정입니다.
2. **실물 재생 확인**: `web_rest` → `web_greet` → `web_tickle` 순서(엔지니어가 옆에서 정지에 손이 닿는 상태로)로 모션이 뷰포트와 같은지 봐야 합니다. 앞서 "인사"에서 기둥이 안 움직인다는 보고가 있었고, 원인은 로봇이 정지 상태에 토크가 꺼져 있던 것으로 추정했습니다(토크 켜기 후 결과 미확인).
3. 좌우 비대칭 표정(윙크, 슬픈 눈, 신난 눈, 눈물 눈)의 좌우 방향은 실물로 아직 다 확인하지 못했습니다(하트 눈·웃는 눈·편안한 눈은 확인함).
4. **표정 모음/간지럽히기의 눈 키**가 프리셋과 조금 다릅니다(직접 만든 키로 보임). 의도한 것이 아니면 프리셋으로 되돌려야 합니다. 움직임 키는 모두 프리셋과 같습니다.
5. 씬이 끝난 뒤 눈은 시간표의 마지막 표정(대부분 졸린 눈)이 유지됩니다(로봇 기본 눈으로 돌릴지는 안 정했음).
6. 웹 모션은 접힌 자세(0°)에서 시작해 제자리로 돌아오게 만들었고 물기(전류 제어) 동작은 없습니다. 시나리오 6(깜짝 놀람)과 표정 모음은 접힌 자세에서 시작하지 않아서 로봇이 먼저 그 시작 자세로 이동합니다.

### 안전 규칙
- 처음 움직일 때는 **사람이 옆에서** 정지/전원에 손이 닿게 합니다. 새 모션은 작은 각도의 씬 하나부터.
- 로봇이 이상하면 `■ 정지`. 토크 해제는 머리가 처질 수 있습니다.
- 웹 화면을 새로고침하면 로봇 연결·동기·주변 확인 체크가 모두 꺼집니다. 다시 켜야 움직입니다.
- **테스트 때 `window.mqtt`를 가짜로 바꿨다면 반드시 새로고침해서 되돌리세요.** 가짜가 남아 있으면 화면은 동작하는데 로봇에는 아무 명령도 가지 않습니다(이전에 이 때문에 "화면에서는 되는데 로봇이 안 움직임"이 있었습니다).

## 10. 작업 방식 (이 프로젝트에서 쓰던 약속)

- 코드 변경은 사용자가 "깃에 반영해줘"라고 할 때만 커밋·푸시합니다. 커밋 메시지는 한글로 씁니다.
- 로봇 파일을 덮어쓰기 전에는 항상 로봇의 `backups/`에 백업하고, 올린 뒤 체크섬(`shasum`/`sha256sum`)을 비교하며, 로봇 로그에서 다시 읽었는지 확인합니다.
- UI는 미니멀·플랫, 다크 베이지 톤, 샴페인 포인트 색. 라운드는 버튼에만, 그림자 없음. 확인·입력 창(`confirm`/`prompt`)은 쓰지 않고 인라인으로 처리합니다.
- 브라우저 모듈 캐시 때문에 코드를 고친 뒤에는 `fetch(파일, {cache:'reload'})`로 다시 받아 새로고침해야 반영됩니다.
