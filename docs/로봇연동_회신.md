# 웹 담당 회신 (엔지니어 답변서 확인 + 남은 항목)

`로봇연동_답변서.md`를 확인했습니다. 답변서 5번(남은 항목)에 대한 웹 쪽 답과, 웹에서 맞추겠다고 한 것들입니다.

## 1. 웹 쪽 답 (답변서 5번)

### 1-1. head는 "목 기준 상대각"입니다
웹 모델에서 머리(head) 본은 기둥(neck) 본의 자식이라, 웹의 head 각도는 **목에 대한 상대각**(본 로컬 각도)입니다.
따라서 ID3 = 3074 + 11.38 × head 로 그대로 쓰면 됩니다(월드 기준 변환 불필요).
참고: 웹에서 헤드가 수평(정면)을 보는 자세는 대략 `head ≈ −1.2 × neck` 입니다.

### 1-2. tilt(갸웃) 부호
웹 모델 기준: **tilt가 + 이면 머리 위쪽이 로봇 기준 오른쪽으로 기웁니다**(정면 축 기준 오른손 법칙).
`check_tilt`에서 ID4 +80틱이 로봇 기준 어느 쪽으로 기우는지만 알려 주시면 확정합니다.
- ID4 + 가 로봇 기준 **오른쪽 갸웃**이면 → `ID4 = 2021 + 11.38 × tilt`
- ID4 + 가 로봇 기준 **왼쪽 갸웃**이면 → `ID4 = 2021 − 11.38 × tilt`

### 1-3. body 부호 (답변서 식과 반대일 수 있음)
웹 모델 기준: **body가 + 이면 로봇이 위에서 볼 때 반시계(로봇 기준 왼쪽)로 돕니다.**
답변서의 `ID1 = 1600 − 29.6 × body`는 "오른쪽 회전을 +로 할 때" 식이므로, 웹의 + 가 왼쪽이면 틱 증가 = 왼쪽 회전(시험으로 확인됨)이라 아래가 됩니다.
- **`ID1 = 1600 + 29.6 × body`** (웹 body + = 로봇 기준 왼쪽 회전)
- `check_body`(ID1 +296틱 = 왼쪽 10° 예상)에서 실제로 **왼쪽**으로 돌면 이 식이 맞습니다. 오른쪽으로 돌면 알려 주세요.

### 1-4. 눈 표정
로봇이 쓰는 영역이 **위 4줄 × 8칸**이라 웹 표정 16종을 4줄 버전으로 새로 만들겠습니다.
기존 이름과의 대응:

| 로봇 | 웹 |
|---|---|
| idle (자동 깜빡임) | 뜬 눈 |
| closed | 감은 눈 |
| happy | 웃는 눈 |
| heart | 하트 눈 |
| (없음 → 추가 요청) | 졸린 눈, 놀란 눈, 반짝 눈, 슬픈 눈, 신난 눈, 윙크, 편안한 눈, 별 눈, 초롱 눈, 눈물 눈, 점 눈, 또렷한 눈 |

4줄 비트맵(왼/오른쪽 눈 각각 4줄×8칸, 비트 7 = 왼쪽 칸)과 애니메이션 프레임 규칙(반짝/별/눈물)을 JSON으로 드리겠습니다.

## 2. 웹에서 하겠다고 한 것

1. **로봇용 내보내기**: 시나리오 → `motions/이름.csv`(절대 틱, 0.1초 간격, 첫 줄 `t,id1,id2,id3,id4`) + 눈 단계가 들어간 씬 조각을 만드는 변환기.
2. **실제 가동 범위로 잘라 내기**: neck 0~34°, head −46.5~0°, tilt는 head 각도별 허용 범위(답변서 3-2 표), body 그대로.
3. **가속도 맞추기**: 관절 가속도를 약 200°/s² 이하로 부드럽게 보정(웹에서 미리 보이는 모션도 같게).
4. **웹 → 로봇 연결 패널**: 부스 브로커 `ws://192.168.1.232:9001`에 접속해 `booth/robot2/cmd`로 씬 실행·정지·토크 해제·표정을 보내는 화면(전시 환경이 오프라인이라 MQTT 라이브러리는 파일로 포함).
5. (선택) **실시간 조그**: 웹 슬라이더 → 로봇. 필요하면 `pose` 명령을 추가해 주세요(예: `{"cmd":"pose","deg":{"neck":10,"head":-12,"tilt":0,"body":0}}`).

## 3. 엔지니어에게 부탁

1. `check_neck / check_head / check_tilt / check_body` 결과: **실제 각도**와 tilt·body가 **로봇 기준 어느 쪽**으로 움직였는지.
2. CSV 형식 확인: 첫 줄 머리글 `t,id1,id2,id3,id4`, 0.1초 간격 절대 틱이 맞는지(맞다면 그대로 만듭니다).
3. 눈 4줄 비트맵을 로봇에 넣을 때 이름을 그대로 쓰는 방식으로 진행해도 되는지.
4. 웹 JSON 샘플은 웹에서 내보내서 드립니다(변환기는 웹 쪽에서 만드는 것으로 진행).
5. `pose`(실시간 조그) 명령이 필요한지 여부.

## 4. 안전 확인 (웹 모션 기준)

- 웹 모션에는 **물기(current 제어) 동작이 없습니다**(위치 모드만 사용).
- 웹 모션은 항상 접힌 자세(0°)에서 시작하고, 끝에 제자리로 돌아오는 구간이 있습니다(시나리오6은 처음/끝 자세가 같음).
- 로봇에서 처음 시험할 때는 **작은 각도의 단일 씬 → 시나리오 1개** 순서로, 엔지니어가 옆에서 정지에 손이 닿는 상태로 진행하겠습니다.
